# 西部牛仔 · 网页版

**开枪、防御、装弹——三个动作，猜中对手的下一步。**

西部牛仔是一款同时行动的回合制对战游戏。你可以与会适应玩家习惯的电脑交手，也可以创建房间，邀请朋友在线对决。既能从零子弹开始快速较量，也能在完整模式中选择初始子弹、争夺筹码，规划最多五轮的胜负。

无需安装客户端，电脑与手机浏览器均可游玩，也支持微信内置浏览器。

**[在线试玩](https://xinbuniuzai-web.onrender.com)** · **[AI 建模报告](完整模式AI模型说明.md)** · **[部署指南](DEPLOY_RENDER.md)** · **[v0.16.0 发布说明](RELEASE_AI_V0_16.md)**

## 游戏特色

- **同时出招，互相预判**：双方先选择，再一起揭示。抓住对手装弹的时机开枪，也要防止自己的习惯被看穿。
- **两种游戏节奏**：快速模式专注一轮内的攻防；完整模式加入初始选弹、筹码与赔付，让同一个动作在不同局势下产生不同价值。
- **人机与联机都可玩**：两种模式均支持电脑对战和房间号联机，电脑、手机可以一起加入房间。
- **会利用玩家习惯的 AI**：结合博弈均衡、行为预测与决策规划；快速模式与完整模式分别维护学习记忆。
- **本地记录与诊断**：浏览器保存人机记忆、分模式战绩和对局记录；完整人机可手动导出决策诊断，便于复盘。
- **可自行部署**：原生 HTML/CSS/JavaScript 前端，Node.js 服务端，WebSocket 联机；运行游戏不需要 Python、GPU 或外部大模型 API。

## 怎么玩

### 每回合的三个动作

双方的当前子弹数公开，本回合选择在双方提交后揭示。

| 动作 | 效果 | 条件 |
| --- | --- | --- |
| 开枪 | 消耗一颗子弹；如果对方正在装弹，立即获胜 | 至少有一颗子弹 |
| 防御 | 挡住对方开枪，对方仍消耗子弹 | 始终可用 |
| 装弹 | 增加一颗子弹，但会被开枪击中 | 子弹未达到上限 10 |

除了开枪击中装弹，双方动作正常结算后，**一方子弹至少为 5 且严格多于对方，也会获胜**。双方同时达到 10 颗子弹为平局；同时开枪则各消耗一颗，再检查局面。

每轮最多 100 回合。第 100 回合先判断本次行动是否产生胜负，仍未结束才判平局。因此，防御虽然能挡住枪，却不能阻止对手靠积累子弹取胜。

### 快速一轮

双方从 **0 颗子弹**开始，按上述规则进行一轮较量，结束后可以再来一局。

适合熟悉规则、练习预判，或与朋友快速对战。

### 完整一局

双方初始各有 **50 筹码**，一局最多 **5 轮**。每轮开始前，双方保密选择 **0～2 颗初始子弹**，随后公开并开始本轮。

轮末按以下规则结算：

- 设双方初始选弹为 i、j，结算子弹差的绝对值为 x，基础赔付为 **y = (i + 1) × (j + 1) × x**。
- 获胜方的结算子弹较多时，对方支付 y；获胜方结算子弹较少时，对方支付 **2y**。这里的“劣势”指子弹较少，不是筹码较少。
- x 为 0 时不转移筹码；平局时双方各扣除 **5 × 自己的初始选弹数**。
- 瞬间胜负也计算结算子弹：开枪方扣一颗，被击中的装弹方不增加子弹。
- 结算后任一方筹码不大于 0，或第五轮结束，整局结束；筹码更多的一方获胜，相同则平局。

例如，双方初始各选 1 颗子弹，某回合你有 1 颗、对手有 4 颗；你开枪击中正在装弹的对手，结算子弹为 0 与 4。基础赔付为 16，因为你以较少子弹获胜，最终获得 32 筹码。

这让完整模式不只是“尽量赢下一轮”：初始选弹、赔付倍率、当前筹码和剩余轮数都会影响值得采取的策略。

### 与朋友联机

进入玩家对决，一方创建房间，另一方输入房间号加入；选择相同游戏模式即可对战。

默认每次选弹或出招限时 60 秒，超时随机代选，连续 3 次超时判负。主动离开立即判负；意外断线有 60 秒重连宽限期，刷新页面可尝试恢复。

人机对战不限时。完整人机需要连接服务器；刷新或退出后重新开局，已保存的行为记忆保留，中途退出不计胜负。

## 电脑如何决策

电脑根据已公开的信息预测玩家行动，并在玩家本次选择揭示前锁定自己的动作。

| | 快速一轮 | 完整一局 |
| --- | --- | --- |
| 玩家预测 | 历史动作统计、均衡先验、上一回合动作对 | 小型神经网络与 814 个行为假设组成的贝叶斯模型库 |
| 决策方法 | 最佳响应与均衡混合，必要时使用记忆策略 | 完整对局均衡、会模拟未来学习的三步前瞻、动态风险余额 |
| 学习时机 | 每局开始读取最新完成日志；局内根据上一动作对选择应对 | 每次揭示后更新行为权重，并回补 0.5% 基础先验；跨轮、跨局保留 |
| 运行位置 | 浏览器 | Node.js 后台线程 |

完整模式优化的是**整局期望得分：胜 1、平 0.5、负 0**。在利用玩家习惯的同时，动态风险余额将相对完整均衡的整局最坏期望得分损失控制在 0.02 以内；这一保证不适用于快速模式。

v0.16.0 完整模式采用 `full-temporal3-belief005-v1` 固定遗忘策略。电脑同时考虑玩家的固定偏好、较长记忆、对电脑历史行为的反制及打法变化；每次公开动作后，预测更符合实际的假设获得更多权重。小幅回补先验，让电脑有机会重新认识改变打法的玩家。

原有 203→96→3 行为网络参数保持固定，在线变化的是公开历史和行为假设的概率，不是在每局里重新训练网络。新后验与最近 64 条事件一起保存在当前浏览器；旧版记忆升级时保留公开历史，新后验从基础先验开始。刷新仍会重新开局，不恢复中途筹码或未揭示动作。

离线研究也尝试过百万样本 GPU 训练的 GRU 和动态神经融合。最新 2,688 局合成对手测试中，固定遗忘版与融合版主要组期望得分均为 86.88%；本次选择运行成本较低的固定遗忘版。新 GRU 和动态融合没有接入本次发布。快速模式同样保留现有统计与记忆策略。

已有研究实验使用合成对手，成绩不能直接解释为真人胜率。发布取舍与验证见 **[v0.16.0 发布说明](RELEASE_AI_V0_16.md)**；原均衡、网络与快速模式的建模细节见 **[两种电脑策略建模报告](完整模式AI模型说明.md)**。

人机记忆与记录保存在当前浏览器，两种模式互相独立，不跨设备同步。完整人机的动作及恢复所需记忆会发送到服务器参与决策；诊断文件由玩家手动导出，未启用自动上传诊断或在线重训。

## 本地运行

需要 Git、Node.js 与 npm。项目声明的 Node.js 最低版本为 16。

```bash
git clone https://github.com/tao3126786377/xinbuniuzai-web.git
cd xinbuniuzai-web
npm ci
npm run build
npm start
```

启动后打开 **[http://localhost:3000](http://localhost:3000)**。

`npm run build` 校验并解压仓库内的完整 AI 资源到 `.runtime/match-ai/`，无需重新训练。压缩资源约 80 MB，解压后的均衡表约 402 MiB，需要预留磁盘空间；浏览器不下载这些表。启动时也会自动准备缺失资源。

### Windows 与局域网游玩

安装 Node.js 后，也可以双击 `start.bat` 启动；首次运行会安装缺失的依赖。

电脑和手机连接同一个局域网，按启动终端显示的局域网地址访问，例如 `http://192.168.1.100:3000`。如防火墙提示，请允许该服务通过所在的专用网络；一台设备创建房间，另一台加入即可。

## 部署

项目包含服务端联机与完整 AI，部署时需要运行 Node.js 服务，不能只把前端文件放到 GitHub Pages。

现有站点使用 Render Web Service，对应仓库设置为：

| 配置 | 值 |
| --- | --- |
| Root Directory | 留空，仓库顶层即应用目录 |
| Build Command | `npm ci && npm run build` |
| Start Command | `npm start` |
| 公网配置 | `ROOM_CODE_LENGTH=5`、`ALLOW_NO_ORIGIN=false` |

也可以在其他支持 Node.js 与 WebSocket 的服务器上运行。更新现有 Render 站点、资源检查与部署验收见 [部署指南](DEPLOY_RENDER.md)。

### 环境变量

以下是服务端默认值；对战限时与断线设置用于玩家联机。

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口 |
| `ROUND_TIMEOUT_MS` | `60000` | 每次选弹／出招时限，毫秒 |
| `GRACE_MS` | `60000` | 断线重连宽限期，毫秒 |
| `TIMEOUT_STRIKES` | `3` | 连续超时判负次数 |
| `ROOM_CODE_LENGTH` | `4` | 房间号位数 |
| `MAX_ROOMS` | `1000` | 房间数量上限 |
| `MAX_ROOMS_PER_IP` | `10` | 每个 IP 的创建房间数上限 |
| `ROOM_TTL_MS` | `600000` | 空房间清理时限，毫秒 |
| `ALLOWED_ORIGINS` | 空 | 额外允许的 WebSocket Origin，逗号分隔 |
| `ALLOW_NO_ORIGIN` | `true` | 是否允许不带 Origin 的连接 |

例如，PowerShell 中可用 `$env:PORT=8080` 设置端口，再运行 `npm start`；Linux/macOS 可使用 `PORT=8080 npm start`。

## 项目结构与开发

```text
public/             网页界面、共享游戏规则、快速模式 AI
lib/match-ai/       完整模式 AI、行为网络与会话接口
assets/match-ai/    完整均衡表的压缩发布资源
tools/              资源准备、策略导出与诊断分析工具
test/               AI 对照、页面、HTTP 与联机测试
research/           离线建模、训练和实验记录
server.js           HTTP 服务与 WebSocket 房间管理
start.bat           Windows 启动入口
```

在仓库根目录安装依赖并构建资源后，可运行以下检查。HTTP 测试使用 Node.js 内置 `fetch`，需 Node.js 18 或以上版本。

```bash
# 快速 AI 数学对照与页面检查
npm run test:ai

# 完整人机页面与 HTTP 会话检查
npm run test:match-web

# 固定遗忘策略、跨局后验、旧记忆迁移、会话隔离与回退
node test/match_ai_belief.js
```

完整 AI 的离线移植对照需要额外生成参考数据，方法见 [模块文档](lib/match-ai/README.md)；离线研究的环境与复跑命令见 [研究说明](research/match_ai/README.md)。Python 是离线研究工具，不是网页服务的运行依赖。

从菜单导出完整人机诊断后，可分析记录：

```bash
node tools/analyze_match_ai.js xnz_match_diagnostics.json
```

快速模式的基础实现源自 C++ 控制台版自适应策略，快速日志格式与原版兼容；完整模式是另行建立的整局模型。日常运行使用仓库已有资源，无需依赖外部 C++ 工程。`npm run gen` 仅用于从原 C++ 工程重新生成快速策略表，需要相邻目录中的源数据文件。
